# The governance control plane, consumed as a PINNED, HASH-VERIFIED dependency.
#
# This repo used to carry a COPY of these modules in lib/controls/. The copy is how the control plane
# drifted apart across four agents while all four integrity locks recorded the same tree hash and
# every CI run was green: this repo HAD the exactly-once FINAL# finalization control and the
# pharmacovigilance and benefits agents did not, and nothing detected that for weeks. For a housing
# assistance workflow the missing control is a duplicate-determination risk: a retried or replayed
# finalize writes a second COMMITTED record, i.e. a second eligibility determination committed for the
# same household — two waiting-list or subsidy decisions of record, and no single answer to "what was
# determined, by whom, on what evidence".
#
# A cross-repo parity check detects that. A dependency PREVENTS it. This is the dependency.
#
#   pip install --require-hashes -r requirements-core.txt
#
# --require-hashes means pip refuses the install if the artifact at that URL ever changes. Bump the
# version AND the hash together; they are published side by side on the release.
#
# Source: https://github.com/virtualryder/governed-core  (Apache-2.0, public)
# Release: https://github.com/virtualryder/governed-core/releases/tag/v1.11.1

#
# WHERE THE HASH COMES FROM (L51, 2026-09-08). Take it from the release's own RELEASE-HASHES.txt,
# never from a wheel you built locally. `gh release create` uploads your local wheel, and the
# release workflow that fires on the same tag then builds its own and REPLACES that asset - so a
# hash verified by downloading the asset immediately after publishing can be correct at the moment
# you check it and stale two minutes later, which is exactly how CI came to fail with
# "THESE PACKAGES DO NOT MATCH THE HASHES" on a hash that had been verified by hand.
# The check that means something is running the install itself:
#     python -m pip install --force-reinstall --require-hashes -r requirements-core.txt
#

    --hash=sha256:149423f0b7d4f68658bfeb72d2b287d52a3aabee225bf2c2ae9f21d87b0f4903
